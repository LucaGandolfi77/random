# Capitolo 3 — I puntatori: l'errore da un miliardo di dollari

**Parte I — L'inizio catchy, che diventa tecnico**

**Parole:** ~1.050

---

> "Lo chiamo il mio errore da un miliardo di dollari. Fu l'invenzione del riferimento null nel 1965."
>
> — Tony Hoare

Nel 1965 Tony Hoare ha inventato il riferimento null, e nel 2009 si è alzato a una conferenza e se ne è scusato, pubblicamente, e la scusa era reale, ed è l'unica scusa nella storia dell'informatica che è costata un miliardo di dollari ed è stata accettata da tutti. Questo capitolo riguarda i puntatori, che sono il fratello maggiore e più duro del riferimento null, e questo capitolo è il capitolo in cui il manuale smette di essere catchy, perché i puntatori sono dove il C++ smette di essere catchy. Tutto ciò che viene prima dei puntatori è un linguaggio. I puntatori sono uno stile di vita.

**Il puntatore, la verità.** Un puntatore è una variabile il cui valore è un indirizzo. È tutto. Non è magia, non è l'orrore, non è la cosa che ne fanno i manuali: è una variabile, e il suo valore è un indirizzo, e l'indirizzo è un numero, e il numero punta — da qui il nome — a una regione di memoria.

```cpp
#include <iostream>

int main() {
    int x = 42;
    int* p = &x;                    // p contiene l'indirizzo di x

    std::cout << x  << '\n';        // 42        (il valore)
    std::cout << &x << '\n';        // es. 0x7ff... (l'indirizzo di x)
    std::cout << p  << '\n';        // lo stesso indirizzo (il valore di p)
    std::cout << *p << '\n';        // 42        (la cosa a cui p punta: il dereference)

    *p = 99;                        // attraverso il puntatore, cambiamo x
    std::cout << x << '\n';         // 99        (x è stato cambiato, attraverso p)
    return 0;
}
```

Leggi le ultime tre righe finché non smettono di essere strane. `*p = 99;` cambia `x`. Non c'è nessuna `x` su quella riga. C'è un puntatore, dereferenziato, e attraverso il puntatore il valore di `x` viene cambiato, e il cambiamento è tutto ciò che è un puntatore: è indirezione. È la capacità di toccare una cosa senza nominarla. E l'indirezione è la cosa che rende il C++ C++: ogni lista concatenata, ogni albero, ogni grafo, ogni buffer, ogni allocazione sull'heap, ogni chiamata di funzione virtuale in un programma grande, ogni polimorfismo, ogni interfaccia in ogni sistema che usi — tutto è indirezione, e tutto è puntatori, e i puntatori sono la cosa che rende il software possibile e la cosa che rende il software pericoloso, ed entrambi i fatti hanno la stessa causa, che è la bellezza della cosa.

**Le operazioni.** I puntatori hanno esattamente sei cose che fai con loro, e le sei cose sono l'intero vocabolario:

```cpp
int x = 42;
int* p = &x;       // 1. address-of:     &x
int y = *p;        // 2. dereference:    *p
++p;               // 3. aritmetica dei puntatori (sui vettori: passa all'elemento successivo)
int* q = nullptr;  // 4. il puntatore nullo: non punta a niente (dal C++11, mai usare NULL o 0)
bool b = p;        // 5. truthiness: è nullo?
int** r = &p;      // 6. puntatore a puntatore (l'orrore; vedi sotto)
```

**L'aritmetica.** L'aritmetica dei puntatori è la cosa che rende il C++ veloce, e la cosa che rende il C++ pericoloso, ed entrambe hanno la stessa causa:

```cpp
int v[5] = {10, 20, 30, 40, 50};
int* p = v;             // i vettori decadono (decay) in puntatori al loro primo elemento
std::cout << *p     << '\n';   // 10
std::cout << *(p+2) << '\n';   // 30   (p+2 avanza di due *int*, non di due byte)
std::cout << p[2]   << '\n';   // 30   (p[2] è *definito* come *(p+2); la parentesi quadra è zucchero sintattico)
```

`p+2` avanza di due *int* — non di due byte. Il compilatore moltiplica per `sizeof(int)`, perché il compilatore sa cosa punta il puntatore, e il sapere si chiama type safety, e il type safety è la cosa che rende l'aritmetica dei puntatori utile. E il pericolo: `p+10` è fuori dai limiti, e fuori dai limiti è comportamento indefinito, e il comportamento indefinito è la cosa che il C++ ti fa, e la cosa che il C++ ti fa è il soggetto del resto della tua vita.

**L'orrore.** `int** r = &p;` — un puntatore a puntatore. E continua: `int***`, `int****`. Nel codice vero, incontrerai `int**` (parametri di output, vettori bidimensionali) e poi, con pietà, si ferma, perché a tre livelli la mente umana si arrende, e l'arrendersi si chiama `std::vector`, e il vector è il capitolo 6, e sei quasi pronto.

**Il decay.** La riga `int* p = v;` — dove `v` è un vettore — contiene la cosa più silenziosamente distruttiva del C++: *il decay da vettore a puntatore*. Un vettore, passato a una funzione, decade in un puntatore, e la dimensione si perde:

```cpp
void printSize(int arr[]) {          // questo è davvero: void printSize(int* arr)
    // sizeof(arr) è sizeof(int*), NON la dimensione del vettore.
    // La dimensione è sparita. È caduta nel decay. Nessuno ti avverte.
}
```

La dimensione cade nel decay, e la perdita è il motivo per cui ogni API C prende un puntatore *e* una lunghezza — `memcpy(dst, src, n)` — e la lunghezza è la cosa che passi male, e il passarla male è il buffer overflow, e il buffer overflow è la classe di vulnerabilità che è costata all'industria più del miliardo di dollari per cui Hoare si è scusato. Il decay è l'errore dell'errore. E la correzione è l'intera proposta del C++: `std::array` (la dimensione viaggia con lui) e `std::vector` (la dimensione vive dentro di lui), ed entrambi sono il capitolo 6, e sei pronto ora, quasi.

**Il null.** `nullptr` — dal C++11 — è il puntatore nullo, ed è l'errore, e l'errore è reale, e la difesa è una riga:

```cpp
if (p) {           // p è non-nullo?
    std::cout << *p << '\n';
}
```

Verifica prima di dereferenziare. Ogni professionista lo sa. Ogni professionista l'ha saltato, una volta, alle 3 di notte, e il saltare è il segfault, e il segfault è onesto, e l'onestà, questa volta, è la cosa che ti ha salvato: il segfault dice *qui*, e il *qui* è dove sta il bug, e lo correggi, e il mondo continua.

Questo è il capitolo. Il puntatore è indirezione. L'indirezione è la cosa che rende il software possibile e pericoloso, ed entrambe hanno la stessa causa. Il decay perde la dimensione. Il null è l'errore da un miliardo di dollari. E l'onestà del segfault è la cosa che ti mancherà in ogni altro linguaggio.

E ora, la pietà: il capitolo 4 sono i riferimenti, e i riferimenti sono i puntatori con l'orrore rimosso.
