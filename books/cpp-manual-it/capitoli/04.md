# Capitolo 4 — I riferimenti: gli alias che ti salvano

**Parte I — L'inizio catchy, che chiude**

**Parole:** ~1.000

---

> "Il C rende facile spararsi in un piede; il C++ lo rende più difficile, ma quando ci riesci ti fa saltare via l'intera gamba."
>
> — Bjarne Stroustrup

Bjarne l'ha detto, e la frase è la cosa più divertente e più vera mai detta sul C++, e questo capitolo riguarda la parte che la rende più difficile: il riferimento. Il riferimento è la risposta del C++ al puntatore, e la risposta è questa: il puntatore con l'orrore rimosso. Questo capitolo chiude la Parte I del manuale, e la chiude con la pietà che il titolo promette.

**Il riferimento, la verità.** Un riferimento è un alias: un altro nome per un oggetto esistente. Non è una variabile (non ha un indirizzo proprio che puoi prendere in modo significativo — be', ha un indirizzo, e l'indirizzo è quello del referente; il riferimento è trasparente). Non è un puntatore. È un secondo nome per la stessa cosa:

```cpp
#include <iostream>

int main() {
    int x = 42;
    int& r = x;                 // r è un altro nome per x. Non una copia. Non un puntatore. Un alias.

    r = 99;                     // attraverso l'alias, cambiamo x
    std::cout << x << '\n';     // 99

    std::cout << &x << '\n';    // es. 0x7ff...
    std::cout << &r << '\n';    // lo stesso indirizzo: il riferimento è trasparente
    return 0;
}
```

I due indirizzi sono gli stessi, perché `r` *è* `x` — non una copia di lui, non un puntatore a lui: un altro nome per lui. Il riferimento è l'alias, e l'alias è la cosa che ti salva dai tre orrori del puntatore:

1. **Niente null.** Un riferimento deve essere inizializzato e non può essere ribindato o reso nullo (legalmente). `int& r = nullptr;` non compila. L'errore da un miliardo di dollari non può essere commesso con un riferimento, perché il riferimento si rifiuta. Questa è la pietà, e la pietà è imposta dal compilatore, che è il miglior tipo di pietà: quella che compila.
2. **Niente aritmetica.** `r + 1` è aritmetica intera sul *valore* (che è quasi sempre quello che intendevi comunque), non aritmetica dei puntatori sull'*indirizzo*. Il decay non può avvenire, perché non c'è niente da far decadere: il riferimento è l'oggetto.
3. **Niente rebinding.** Una volta che `r` è un alias per `x`, è un alias per `x` per sempre. Non puoi farlo diventare un alias per `y`. `r = y;` assegna *il valore* di `y` a `x` (attraverso l'alias), che è quasi sempre quello che intendevi. Il rebinding silenzioso del puntatore — il bug in cui il tuo puntatore silenziosamente comincia a puntare altrove — non può avvenire.

**L'uso vero: il passaggio per riferimento.** Ecco la cosa che userai ogni giorno per il resto della vita:

```cpp
#include <iostream>
#include <string>

void grow(std::string& s) {        // per riferimento: modifichiamo la stringa del chiamante
    s += " (cresciuta)";
}

void print(const std::string& s) { // per *const* riferimento: niente copia, niente modifica
    std::cout << s << '\n';
}

int main() {
    std::string s = "Hello";
    grow(s);
    print(s);                      // Hello (cresciuta)
    return 0;
}
```

Due funzioni, e la differenza è l'intera filosofia del passaggio di argomenti del C++. `grow` prende per riferimento e modifica la stringa del chiamante — niente copia, niente ritorno, niente sintassi da puntatore. `print` prende per *const* riferimento: niente copia (la stringa non è duplicata — per una stringa lunga, la copia è il costo), e niente modifica (il `const` lo impone). Il `const&` è il cavallo di battaglia di tutto il codice C++: *passa tutto ciò che è grande per const riferimento*, e non pagherai mai una copia che non volevi, e non modificherai mai una cosa che non intendevi.

**Le eccezioni, dichiarate onestamente.** Tre casi in cui *non* usi `const&`:

1. **Tipi piccoli** — `int`, `double`, puntatori, iteratori: passa per valore. La copia è più economica dell'indirezione, e l'indirezione può sconfiggere l'ottimizzatore.
2. **Copiavi comunque** — se la funzione conserva l'argomento, prendi per valore e usa `std::move` (il capitolo 8 farà diventare questa frase sensata).
3. **Volevi una copia** — ovviamente.

E due casi in cui il riferimento *è* pericoloso, dichiarati onestamente: il riferimento dangling (restituire un riferimento a una variabile locale, e la locale muore, e il riferimento resta appeso, e l'appeso è comportamento indefinito — il riferimento ha il peggiore crimine del puntatore, una volta, e il `-Wall` del compilatore lo beccherà di solito) e la confusione delle durate di vita (il riferimento non estende la vita di niente; lo nomina soltanto). La pietà non è totale. Il C++ non fa pietà totale. Il C++ fa pietà parziale con onestà totale, e l'onestà è il matrimonio.

**La regola del pollice, per la vita:**

```cpp
void f(Widget& w);            // Lo modificherò. Niente copia. Deve esistere.
void g(const Widget& w);      // Lo leggerò soltanto. Niente copia. Deve esistere.
void h(Widget w);             // Lo copierò (piccolo) o lo possiederò (e farò move, capitolo 8).
void k(Widget* w);            // Potrebbe arrivarmi niente: nullptr è possibile. (Ultima risorsa.)
```

Quattro righe, e le quattro righe sono l'intero passaggio di argomenti del C++, e se le interiorizzi — davvero, nelle dita, alle 3 di notte — hai imparato la cosa che separa i professionisti dai turisti, e i turisti, in questa metafora, sono quelli che passano tutto per valore e rilasciano il bug di performance, e i professionisti sono quelli che scrivono `const&` dormendo.

Questo è il capitolo, e chiude la Parte I. Ora sai: le variabili sono regioni di memoria, i tipi sono contratti, i puntatori sono indirezione, i riferimenti sono alias, e il segfault è onesto. La Parte II è dove diventa tecnico, e la Parte II comincia con la filosofia che tiene insieme tutto il C++ moderno: RAII, l'arte di pulire dopo di sé, automaticamente.
