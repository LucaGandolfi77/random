# Capitolo 5 — RAII: pulire dopo di sé, automaticamente

**Parte II — Il centro tecnico**

**Parole:** ~1.050

---

> "Esistono solo due tipi di linguaggi: quelli di cui le persone si lamentano e quelli che nessuno usa."

> — Bjarne Stroustrup

La Parte II comincia, e la Parte II è tecnica, e la Parte II comincia con l'idea più importante del C++ moderno — più importante dei template, più importante della move semantics (la semantica di spostamento), più importante di qualsiasi cosa il linguaggio abbia aggiunto dal 1995 — e l'idea ha un nome che la nasconde: **RAII**, Resource Acquisition Is Initialization. Il nome nasconde l'idea come il nome "La morte di Ivan Il'ič" nasconde la più grande novella mai scritta: il nome è uno spoiler che non lo è, perché non lo capisci finché non l'hai vissuto, e una volta vissuto, non puoi tornare indietro.

**Il problema, precisamente.** In C, le risorse sono gestite a mano:

```c
/* C: la risorsa e la pulizia sono due righe diverse, e lo spazio tra loro è dove vivono i bug */
FILE* f = fopen("data.txt", "r");
if (!f) return -1;
/* ... venti righe di codice, ognuna delle quali potrebbe fare return anticipato, throw, o loopare per sempre ... */
if (error) { fclose(f); return -1; }   /* ti sei ricordato? */
/* ... altre venti righe ... */
fclose(f);                              /* e questa: il percorso ci è arrivato? */
```

Ogni percorso tra acquisizione e pulizia deve rilasciare la risorsa. Ogni return anticipato, ogni ramo d'errore, ogni modifica di manutenzione fatta da un junior alle 17 di un venerdì. Lo spazio tra le due righe è dove leakano i file handle, e i leak sono la cosa che butta giù il server, e il server è la cosa che ti sveglia alle 3 di notte, e le 3 di notte sono dove è cominciato questo manuale.

**L'idea, precisamente.** Il C++ lega la risorsa alla *durata di vita* (lifetime) di un oggetto. Acquisisci nel costruttore; rilasci nel distruttore. Il linguaggio garantisce — il compilatore lo impone, meccanicamente, per ogni percorso, inclusi i percorsi che non esistono ancora — che il distruttore giri quando lo scope dell'oggetto finisce. Ogni return, ogni eccezione, ogni ramo:

```cpp
#include <cstdio>
#include <stdexcept>

class File {
public:
    explicit File(const char* path) : f_(std::fopen(path, "r")) {
        if (!f_) throw std::runtime_error("impossibile aprire il file");
    }                                     // acquisizione: nel costruttore
    ~File() { if (f_) std::fclose(f_); }  // rilascio: nel distruttore. Sempre. Ogni percorso.
    File(const File&) = delete;           // non copiabile (due oggetti, un file: no)
    File& operator=(const File&) = delete;
    std::FILE* get() const { return f_; }
private:
    std::FILE* f_;
};

int load(const char* path) {
    File f(path);                         // acquisito qui
    if (something_wrong()) return -1;     // il distruttore gira QUI, automaticamente
    if (other_error()) throw std::runtime_error("bad");  // il distruttore gira ANCHE qui
    /* ... */
    return 0;                             // il distruttore gira QUI, alla fine dello scope
}                                         // e qui. Lo spazio tra le righe è sparito.
```

Leggi i commenti. Ogni percorso rilascia il file. Il return anticipato lo rilascia. L'eccezione lo rilascia. La modifica di manutenzione — la modifica del venerdì del junior, il ramo nuovo, il refactor — lo rilascia, perché il rilascio non è una riga di codice: è una proprietà della durata di vita dell'oggetto. Lo spazio tra le due righe — lo spazio dove vivevano i bug — è sparito. Non ridotto. Sparito. Il compilatore lo ha chiuso, meccanicamente, per ogni percorso che esiste e per ogni percorso che verrà aggiunto.

**Il nome, decodificato.** "Resource Acquisition Is Initialization" significa: *l'acquisizione della risorsa coincide con l'inizializzazione dell'oggetto*. La nascita dell'oggetto è l'acquisizione della risorsa; la morte dell'oggetto è il rilascio della risorsa. E la durata di vita — la nascita e la morte — è il lavoro del linguaggio, non il tuo. Questa è l'idea più profonda del C++: **il linguaggio gestisce il tempo, e tu gestisci le cose.** Ogni altro linguaggio con garbage collector gestisce la memoria tracciando ciò che è vivo, a runtime, con una pausa. Il C++ la gestisce con lo scope, in tempo di compilazione, con zero pause. Il tracciamento è una tassa pagata ogni ciclo; lo scoping è una tassa pagata una volta, nel design.

**La prova che compone.** Il vero potere non è una classe. È che RAII compone:

```cpp
void transaction(Database& db, Network& net) {
    auto tx = db.begin();          // RAII: fa rollback all'uscita dello scope, a meno del commit
    auto guard = net.suspend();    // RAII: riprende all'uscita dello scope
    /* ... qualsiasi codice, qualsiasi throw, qualsiasi return anticipato ... */
    tx.commit();                   // esplicito: solo quando tutto ha funzionato
}                                  // ogni guard rilasciato, in ordine inverso, automaticamente
```

Gli oggetti RAII annidati si rilasciano in *ordine inverso* rispetto alla costruzione — lo standard lo garantisce — e l'ordine inverso è l'ordine corretto (un file aperto dentro una transazione si rilascia prima della transazione; la transazione fa rollback delle modifiche del file). La composizione è automatica, corretta e gratis. Questa è la cosa che rende il codice C++ moderno sicuro senza un garbage collector: non disciplina — *meccanismo*. La disciplina è una speranza; il meccanismo è una garanzia. E la garanzia, alle 3 di notte, è la cosa che ti fa dormire: il server non leakà, perché lo spazio tra le righe non esiste.

**Dove lo conosci già.** Hai usato RAII se hai usato: `std::string` (il buffer è la risorsa), `std::vector` (il blocco heap è la risorsa), `std::fstream`, `std::unique_ptr`, `std::lock_guard`, `std::jthread` — tutto del capitolo 6 e del capitolo 9. L'intera libreria standard è RAII, dall'alto in basso, e l'intero linguaggio è costruito per supportarla, e il supporto è la ragione per cui il linguaggio è sopravvissuto: i linguaggi che gestiscono il tempo con lo scope non hanno bisogno di collector, e i linguaggi che non hanno bisogno di collector non fanno pause, e il no-pause è la cosa che i sistemi esigono.

Questo è RAII. Il nome lo nasconde; l'idea è lui: *lo spazio tra le due righe è sparito*. Il resto della Parte II è questa idea, applicata: la libreria standard (capitolo 6), i template (capitolo 7), le move (capitolo 8), gli smart pointer (capitolo 9) — che sono RAII per i puntatori, e la morte di `delete`, e la morte di `delete` è la migliore notizia di questo manuale.
