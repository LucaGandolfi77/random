# Capitolo 6 — La libreria standard: addio, strlen

**Parte II — Il centro tecnico**

**Parole:** ~1.050

---

> "Nel dubbio, usa la forza bruta."
>
> — Ken Thompson

Ken Thompson l'ha detto, e ha co-inventato Unix, e la frase è il consiglio più divertente dell'informatica perché è anche il miglior consiglio, a volte, e l'"a volte" è la cosa di cui tratta questo capitolo: la libreria standard è la forza bruta che qualcun altro ha scritto, testata e ottimizzata, e usarla non è pigrizia — è il più fine atto di umiltà del professionista. Questo capitolo è il tour, e il tour comincia con la frase del titolo: addio, `strlen`.

**La morte di strlen, precisamente.** Ecco il C:

```c
/* C: la stringa è un puntatore e una preghiera */
size_t n = strlen(s);          /* O(n): percorre la stringa, contando, finché trova '\0' */
char* copy = malloc(n + 1);    /* +1: il terminatore. Dimenticalo: il buffer overflow */
strcpy(copy, s);               /* e prega che la source avesse davvero il terminatore */
```

Tre righe, e le tre righe contengono: una scansione O(n) del terminatore, un off-by-one in attesa di succedere (+1), e una preghiera. La lunghezza della stringa non è *nella* stringa; la lunghezza è *implicata* dal terminatore, e l'implicazione è la casa del buffer overflow. Ora il C++:

```cpp
#include <string>
#include <iostream>

int main() {
    std::string s = "Hello, World!";
    std::cout << s.size() << '\n';      // 13: O(1). La lunghezza vive NELLA stringa.
    std::string copy = s;               // una copia profonda completa: niente malloc, niente +1, niente preghiera
    copy += " E altro.";                // cresce da sola; rialloca se serve; niente overflow
    std::cout << copy << '\n';
    return 0;
}
```

`s.size()` è O(1) — tempo costante, garantito dallo standard — perché la lunghezza vive *dentro* la stringa, come membro, mantenuta dall'oggetto. Questo è RAII (capitolo 5) applicato alla struttura dati più usata dell'informatica: il buffer è la risorsa, l'oggetto lo possiede, il distruttore lo rilascia, e la dimensione è un fatto, non una scansione. La preghiera è sparita. Il +1 è sparito. L'off-by-one è sparito. E la stringa cresce da sola — `+=` rialloca quando serve, con una strategia di crescita (tipicamente geometrica, ×1.5 o ×2) — e la riallocazione è fatta da qualcuno che l'ha testata, e il qualcuno è la libreria standard, e la libreria standard è la forza bruta di cui Ken Thompson approverebbe: è forza bruta, scritta una volta, dai migliori.

**Il vector, il cavallo di battaglia.** Se impari un contenitore, impara `std::vector` — e la promessa del manuale è che questa frase non è un'opinione: è il consenso di trent'anni di C++:

```cpp
#include <vector>
#include <algorithm>

int main() {
    std::vector<int> v {5, 3, 1, 4, 2};
    v.push_back(6);                     // append O(1) ammortizzato
    std::sort(v.begin(), v.end());      // O(n log n), il miglior sort mai scritto
    // range-for (C++11): il loop che ha ucciso i bug degli indici
    for (int x : v) { /* ... */ }
    // range-for con l'indice (stile C++20/23):
    for (auto it = v.begin(); it != v.end(); ++it) { *it *= 2; }
    return 0;
}
```

`std::vector` è: un array dinamico, contiguo in memoria (cache-friendly — questa è la ragione profonda per cui vince: l'hardware ama la contiguità), append O(1) ammortizzato, accesso casuale O(1), RAII dall'alto in basso, e il contenitore di default per tutto. La regola, dai professionisti: **"Usa vector come default. Usa qualcos'altro solo quando hai una ragione misurata."** La ragione misurata è la parola chiave: misura prima (il male di Knuth, di nuovo), e la misura dice "vector" novantacinque volte su cento.

**Gli algoritmi, la ricchezza.** La libreria standard ha più di cento algoritmi, e sono la ricchezza del linguaggio:

```cpp
#include <vector>
#include <algorithm>
#include <numeric>

std::vector<int> v {5, 3, 1, 4, 2};
auto it = std::find(v.begin(), v.end(), 4);          // find
bool has = std::any_of(v.begin(), v.end(), [](int x){ return x > 4; });  // any_of + lambda (C++11)
int sum = std::accumulate(v.begin(), v.end(), 0);    // somma
std::sort(v.begin(), v.end());                       // sort
std::reverse(v.begin(), v.end());                    // reverse
auto m = std::minmax_element(v.begin(), v.end());    // min e max, un solo passaggio
```

E il C++20 li ha resi leggibili — la libreria **ranges**:

```cpp
#include <ranges>
#include <vector>
#include <algorithm>

std::vector<int> v {5, 3, 1, 4, 2};
auto pari = v | std::views::filter([](int x){ return x % 2 == 0; })
             | std::views::transform([](int x){ return x * 10; });
for (int x : pari) { /* 20, 40 — lazy, niente contenitori intermedi */ }
```

La pipe — `|` — è la filosofia Unix, tornata a casa: la pipeline, nel linguaggio, tipizzata e lazy. Le views sono lazy — niente gira finché non iteri — e la laziness è performance gratis: niente contenitori intermedi, niente vettori temporanei, niente copie. Il range-for ha ucciso i bug degli indici; i ranges hanno ucciso il rumore delle coppie di iteratori; ed entrambi sono C++20, e il C++20 è il capitolo 11, e sei vicino.

**Gli altri contenitori, l'onestà.** La libreria ne ha altri, e ognuno ha una ragione misurata:

- `std::map` / `std::set` — ordinati, alberi red-black, O(log n); usali quando ti serve l'ordine o l'iterazione stabile.
- `std::unordered_map` / `std::unordered_set` — tabelle hash, O(1) in media; il default per le ricerche.
- `std::deque` — coda a doppia estremità; O(1) push a entrambe le estremità.
- `std::array` — un array a dimensione fissa *la cui dimensione viaggia con lui* (il decay è morto; la vendetta del capitolo 3).
- `std::list` — una lista doppiamente concatenata; quasi mai quello che vuoi (la cache lo detesta), e l'onestà di dirlo è la promessa del manuale.

E le stringhe, gli stream, il filesystem (`std::filesystem`, C++17 — l'iterazione delle directory che ha ucciso le preghiere di `opendir`), il tempo (`std::chrono`, il tempo tipizzato — i nanosecondi sono un tipo, e i tipi non si mescolano, e il non mescolarsi è la morte del bug), i thread (capitolo 10), e la gestione degli errori (`std::expected`, C++23 — l'errore che è un valore, e il valore non fa throw).

Questo è il tour. La libreria standard è la forza bruta scritta una volta dai migliori, e usarla è la più fine umiltà del professionista. Addio, `strlen`. Addio, le preghiere. La libreria le ha tutte, testate, tipizzate, e O(1) dove conta — e l'O(1), nel capitolo 7, diventa l'O(tu): i template, il codice che scrive codice.
