# Capitolo 7 — I template: il codice che scrive codice

**Parte II — Il centro tecnico**

**Parole:** ~1.100

---

> "Un linguaggio che non influenza il tuo modo di pensare la programmazione non vale la pena di essere conosciuto."
>
> — Alan Perlis

Questo è il capitolo che influenza il tuo modo di pensare la programmazione, e lo influenza nella direzione di cui nessuno ti avverte: i template non sono una feature. I template sono un *secondo linguaggio*, che vive dentro il C++, eseguito in tempo di compilazione, Turing-completo, con una sintassi progettata per un'idea più semplice e poi stirata — da trent'anni di uso — nel meccanismo di astrazione più potente e più temuto dell'industria. Questo capitolo lo insegna, tecnicamente e precisamente, e comincia con la paura, perché la paura è la prima cosa che incontri.

**La paura, precisamente.** Chiunque abbia usato C++ l'ha vista: il messaggio d'errore dei template. Quattromila righe. Duemila righe. Un solo errore, stampato come un romanzo, perché il template è stato istanziato — il codice è stato scritto, dal compilatore, dal tuo codice — e l'istanziazione è fallita quattro livelli in profondità, e il compilatore ha stampato tutti e quattro i livelli, con tutti i tipi, dettati per esteso, a ogni livello. Il messaggio d'errore è il romanzo, e il romanzo è il motivo per cui le persone temono i template, e la paura è al contrario: la lunghezza del messaggio d'errore è il *prezzo del potere*, e il potere è questo — **i template sono il codice che scrive codice**, e quando la scrittura del codice va storta, il messaggio d'errore ti dice tutto ciò che è stato scritto, a ogni livello, che è quattromila righe di onestà. L'errore Python per la stessa cosa sarebbe di tre righe e un'alzata di spalle. Il C++ ti dà l'intero romanzo. Impari a leggere le ultime duecento righe, dove vive il problema vero, e la lettura è una skill, e la skill vale la paura.

**L'idea, precisamente.** Un template è un pattern. Il compilatore riempie il pattern con i tuoi tipi:

```cpp
template <typename T>
T massimo(const T& a, const T& b) {
    return (a < b) ? b : a;
}

int    main() {
    int    i = massimo(3, 7);            // T = int.   Il compilatore scrive: int massimo(const int&, const int&)
    double d = massimo(3.5, 2.5);         // T = double. Un'altra funzione completa, scritta per te.
    return 0;
}
```

`massimo<int>` e `massimo<double>` sono *due funzioni diverse*, scritte dal compilatore, dal tuo unico pattern. Il compilatore ha scritto il codice. Tu hai scritto il codice che scrive il codice. E la scrittura si chiama *istanziazione*, e avviene in tempo di compilazione, e il codice istanziato è veloce come codice scritto a mano — zero costo a runtime, niente boxing, niente dispatch — che è la cosa che separa i template da ogni altro meccanismo di astrazione dell'industria: l'astrazione è gratis.

**Il contenitore generico, precisamente.** L'uso vero: il contenitore che funziona per tutto:

```cpp
template <typename T>
class Pila {
public:
    void push(const T& value) { dati_.push_back(value); }
    void pop()                { dati_.pop_back(); }
    const T& top() const      { return dati_.back(); }
    bool empty() const        { return dati_.empty(); }
    std::size_t size() const  { return dati_.size(); }
private:
    std::vector<T> dati_;     // RAII, dal capitolo 5: la memoria è un problema del vector
};
```

Una `Pila` sola, scritta una volta, funziona per `int`, `std::string`, `Widget`, qualsiasi cosa — e la gestione della memoria è un problema del `vector` (RAII compone attraverso i template: l'astrazione è sicura *e* gratis). Questa è la cosa che il C++ fa che nessun altro linguaggio mainstream fa senza costo a runtime: il codice generico è compilato *per tipo*, specializzato, inlined, ottimizzato — l'astrazione sparisce nel codice macchina. L'astrazione è una finzione del codice sorgente; il codice macchina è come se l'avessi scritto a mano. Questo si chiama *astrazione a costo zero*, ed è la decisione di design più profonda del C++, e la regola di Stroustrup è: **"Ciò che non usi, non lo paghi."** La regola è la costituzione del linguaggio.

**I concepts, la correzione della paura (C++20).** Per venti anni, la risposta a "cosa serve a T?" era la documentazione e la speranza. Il C++20 ha aggiunto i **concepts** — requisiti compile-time con nome — e i concepts sono la correzione:

```cpp
#include <concepts>

template <typename T>
concept Numerico = std::integral<T> || std::floating_point<T>;

template <Numerico T>                      // T deve essere numerico: il compilatore lo impone
T massimo(const T& a, const T& b) {
    return (a < b) ? b : a;
}

massimo(3, 7);        // OK: int è Numerico
massimo("a", "b");    // ERRORE: una riga. Il concept dice cosa non va, in una riga.
```

L'errore è di una riga ora. Il concept dice cosa non va, in una riga, in linguaggio umano: *il tipo non è numerico*. Il romanzo di quattromila righe è diventato una frase, e la frase è il regalo più fine del C++20, e il regalo è la correzione della paura: vincoli, con nome, imposti, e leggibili. Usali. Ogni professionista che è passato al C++20 ha smesso di temere gli errori, e il non temere è la cosa che rende i template usabili, e l'usabile è la cosa che sono sempre stati — la paura era il prezzo della diagnostica, e il C++20 l'ha pagato.

**Il calcolo in tempo di compilazione, precisamente.** I template sono Turing-completi: possono calcolare, in tempo di compilazione:

```cpp
template <unsigned N>
struct Fattoriale {
    static constexpr unsigned long long value = N * Fattoriale<N - 1>::value;
};

template <>
struct Fattoriale<0> {                       // il caso base: la specializzazione
    static constexpr unsigned long long value = 1;
};

int main() {
    constexpr auto f = Fattoriale<20>::value;   // calcolato IN TEMPO DI COMPILAZIONE. 2.432.902.008.176.640.000.
    return f > 0 ? 0 : 1;
}
```

`Fattoriale<20>::value` è calcolato dal compilatore, in tempo di compilazione, e il runtime riceve una costante — zero costo, zero runtime, il lavoro fatto nel compilatore. Questa è la macchina che scrive codice *e* lo esegue, prima che il programma esista. E `constexpr` (capitolo 2) è la sintassi più amichevole per lo stesso potere, e l'amichevolezza è il motivo per cui usi `constexpr` quando puoi e i template quando devi — e "quando devi" è più spesso di quanto pensi: ogni libreria, ogni algoritmo generico, ogni contenitore type-safe in ogni sistema che usi sono template, e i template sono il codice che ha scritto il codice, e il codice è gratis.

Questo è il capitolo. I template sono un secondo linguaggio, compile-time, Turing-completi, a costo zero, e i messaggi d'errore sono romanzi che il C++20 ha trasformato in frasi. La paura è pagata. Il potere no.
