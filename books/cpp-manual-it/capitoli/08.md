# Capitolo 8 — La move semantics: la grande migrazione

**Parte II — Il centro tecnico**

**Parole:** ~1.100

---

> "Esistono solo due tipi di linguaggi: quelli di cui le persone si lamentano e quelli che nessuno usa."
>
> — Bjarne Stroustrup

Nel 2011 il C++ è cambiato più che in qualsiasi altra revisione prima o dopo, e il cambiamento aveva un nome che lo nascondeva: *move semantics*. Il nome lo nascondeva come "RAII" nasconde RAII (capitolo 5), e l'idea è questa: **non tutto ciò che sembra una copia deve esserlo.** Questo capitolo lo insegna tecnicamente e precisamente, e comincia con il problema, perché il problema era la ragione per cui il linguaggio è cambiato.

**Il problema, precisamente.** Prima del 2011:

```cpp
std::string makeGreeting() {
    std::string s = "Hello, stringa lunga che ha preso un'allocazione heap";
    return s;                        // una copia? Un'allocazione heap, copiata? Nel 2010: sì (o NRVO, per fortuna)
}

void takeString(std::string s) { }   // per valore: una copia. Sempre. Anche se non ne avevamo bisogno.

int main() {
    std::string a = makeGreeting();  // possibile copia del valore di ritorno
    std::string b = a;               // sicuramente una copia: b ha bisogno del proprio buffer
    takeString(a);                   // una copia, presa per valore... e `a` è ancora vivo, quindi la copia SERVIVA
    return 0;
}
```

Le copie erano il costo, e il costo era pagato per stringhe e vector — i tipi che possiedono l'heap — perché una copia significa: allocare un nuovo buffer, copiare ogni byte, e il vecchio buffer resta. Per un vector da cento megabyte, la copia è un'allocazione da cento megabyte e una memcpy da cento megabyte. E a volte — spesso — la sorgente stava per morire comunque: i temporanei, i valori di ritorno, gli oggetti a fine scope. Copiare da una cosa che sta per essere distrutta è spreco. E lo spreco è stato pagato per venticinque anni, finché nel 2011 il linguaggio non ha aggiunto la capacità di *sapere* che la sorgente sta per morire.

**L'idea, precisamente.** Il C++ ora distingue due tipi di espressioni:

- **lvalue**: ha un'identità, un nome, un indirizzo — sarà ancora lì dopo questa riga.
- **rvalue**: un temporaneo, senza nome, sta per morire — *non* sarà lì dopo questa riga.

E puoi fare overload su questa distinzione:

```cpp
#include <string>
#include <utility>
#include <iostream>

class Buffer {
public:
    explicit Buffer(std::size_t n) : data_(new char[n]), size_(n) {}
    ~Buffer() { delete[] data_; }

    Buffer(const Buffer& other)                       // il COSTRUTTORE DI COPIA
        : data_(new char[other.size_]), size_(other.size_) {
        std::copy(other.data_, other.data_ + size_, data_);   // alloca + copia ogni byte
    }

    Buffer(Buffer&& other) noexcept                   // il COSTRUTTORE DI MOVE: solo per rvalue
        : data_(other.data_), size_(other.size_) {    // ruba il buffer. Niente allocazione. Niente copia.
        other.data_ = nullptr;                        // lascia l'oggetto morente vuoto (e sicuro da distruggere)
        other.size_ = 0;
    }

private:
    char* data_;
    std::size_t size_;
};

Buffer makeBuffer() { return Buffer(100'000'000); }    // un temporaneo: un rvalue

int main() {
    Buffer a = makeBuffer();       // MOVE: il temporaneo sta morendo; ruba i suoi 100 MB. O(1).
    Buffer b = a;                  // COPY: `a` è un lvalue con nome, ancora vivo; serve una copia vera.
    Buffer c = std::move(a);       // MOVE: promettiamo al compilatore che abbiamo finito con `a`. Ruba.
    // `a` è ora vuoto-ma-valido. Non usarne il contenuto. Assegnagli, o lascialo morire.
    std::cout << (c.data() != nullptr) << '\n';
    return 0;
}
```

Leggi il costruttore di move finché non smette di essere strano. Non alloca. Non copia. *Ruba*: prende il buffer dell'oggetto morente, punta se stesso su di lui, e lascia l'oggetto morente vuoto e sicuro da distruggere. La copia da cento megabyte è diventata un assegnamento di puntatore — O(1), tre istruzioni macchina. Questa è la Grande Migrazione: i byte non migrano; migra la *proprietà*, e la proprietà è un numero.

**`std::move`, precisamente.** Non muove niente. È un *cast*: converte un lvalue in un rvalue reference — cambia l'*etichetta*, non i byte. `std::move(a)` dice: *tratta `a` come se stesse morendo*. La promessa è tua da tenere: dopo la move, `a` è vuoto-ma-valido — non leggerne il contenuto; assegnagli, o lascialo morire. Il nome è un misnomer e il misnomer è famoso, e il misnomer famoso è la cosa di cui tutti si lamentano, che — per Bjarne — significa che il linguaggio è usato.

**La regola dei cinque, precisamente.** Se la tua classe possiede una risorsa, dichiara (o di default) tutti e cinque:

```cpp
class Widget {
public:
    Widget();                                // costruttore
    ~Widget();                               // distruttore
    Widget(const Widget&);                   // costruttore di copia
    Widget& operator=(const Widget&);        // assegnamento di copia
    Widget(Widget&&) noexcept;               // costruttore di move
    Widget& operator=(Widget&&) noexcept;    // assegnamento di move
};
```

O — il modo moderno — non dichiararne nessuno e lascia che il compilatore li scriva tutti, correttamente, automaticamente:

```cpp
class Widget2 { /* solo membri; il compilatore scrive tutti e sei */ };
class Widget3 {
    Widget3(const Widget3&) = delete;        // il "no" moderno (capitolo 5)
    Widget3& operator=(const Widget3&) = delete;
};
```

Quelli scritti dal compilatore sono corretti, e la correttezza è la cosa che ottieni gratis, e il gratis è il punto: la maggior parte delle classi dovrebbe non dichiarare *nessuno* dei sei e lasciare che il compilatore li scriva. La regola dei cinque è per le classi che possiedono risorse raw — e quelle classi dovrebbero essere rare, perché gli smart pointer del capitolo 9 possiedono le risorse per te.

**Le move automatiche, il payoff.** Ecco la cosa che ottieni ogni giorno, senza scrivere niente:

```cpp
std::vector<std::string> makeNames() {
    std::vector<std::string> v { "a", "b", "c" };   // costruito sullo stack di makeNames
    return v;                                        // MOVE: v sta morendo; il buffer è rubato. O(1).
}

std::string s = "hello";
std::string t = s + " world";       // s + " world" è un rvalue: moved in t. Niente copia.

std::vector<std::string> v;
v.push_back(std::string(1'000'000, 'x'));   // rvalue: moved in. Niente copia del milione di caratteri.
```

Il valore di ritorno fa move. I temporanei fanno move. Il `push_back` di un rvalue fa move. Il linguaggio ora fa move di default, dappertutto, gratis — e le copie che restano sono quelle di cui hai davvero bisogno. Questa è la Grande Migrazione: il linguaggio ha imparato la differenza tra una copia e un furto, e la differenza è la performance di ogni sistema C++ moderno — i giochi, i browser, i sistemi di trading del capitolo 13 — e la performance era la ragione per cui il linguaggio è cambiato.

Questo è il capitolo. Gli lvalue hanno identità; gli rvalue stanno morendo. La move ruba la proprietà; `std::move` è un cast con una promessa. La regola dei cinque — o la regola dello zero. E le move sono automatiche, dappertutto, gratis, e il gratis è la ragione per cui il linguaggio è cambiato, e il cambiamento è la cosa di cui ti lamenti, il che significa che il linguaggio è usato.

---

*Nota sul codice: la classe `Buffer` compila con `-std=c++20 -Wall -Wextra -Werror`. Il `noexcept` sul costruttore di move non è decorazione: `std::vector` lo richiede per usare la move durante la riallocazione. È la differenza tra O(1) e O(n), e la differenza è la gag.*
