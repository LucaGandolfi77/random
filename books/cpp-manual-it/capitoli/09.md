# Capitolo 9 — Gli smart pointer: la morte di delete

**Parte II — Il centro tecnico**

**Parole:** ~1.100

---

> "Lo chiamo il mio errore da un miliardo di dollari. Fu l'invenzione del riferimento null nel 1965."
>
> — Tony Hoare

Tony Hoare si è scusato per il riferimento null, e la scusa è stata accettata, e il riferimento null è ancora qui. Questo capitolo riguarda l'*altro* errore — il puntatore possessore raw, e il `delete` che deve seguirlo, e lo spazio tra `new` e `delete` dove vivono i leak e i double-free — e questo capitolo è la migliore notizia di questo manuale: **l'errore è stato corretto. È stato corretto dal 2011. E la correzione è gratis.** Questa è la morte di `delete`, e la morte è reale, e nessuno te l'ha detto.

**Il problema, precisamente.** I puntatori possessori raw:

```cpp
void vecchioModo() {
    Widget* w = new Widget();     // acquisito
    /* ... venti righe, ognuna delle quali potrebbe fare return anticipato o throw ... */
    if (error) return;            // LEAK. Il Widget è perduto. Nessuno lo cancella. Mai.
    delete w;                     // se arriviamo qui: bene. Siamo arrivati qui?
}

void modoPeggiore() {
    Widget* w = new Widget();
    delete w;
    delete w;                     // DOUBLE FREE: comportamento indefinito. L'heap è corrotto.
}                                 // e la corruzione è la cosa che esplode, dopo, altrove,
                                  // in un file che non c'entra niente con questo. Il peggiore tipo di bug.
```

Tre modalità di fallimento, e le tre sono la storia dei bug di memoria del C++: il leak (return anticipato), il double-free (confusione di proprietà), e l'uso dopo il free (il puntatore che sopravvive all'oggetto). Lo spazio tra `new` e `delete` è dove vivono, e lo spazio è lo stesso spazio che RAII ha chiuso nel capitolo 5 — e la risposta del capitolo 5, applicata ai puntatori, è lo smart pointer.

**La correzione: `std::unique_ptr`, precisamente.** Proprietà esclusiva, RAII, zero overhead:

```cpp
#include <memory>
#include <cstdio>

void modoModerno() {
    auto w = std::make_unique<Widget>();   // acquisito. Posseduto. Esclusivamente.
    /* ... qualsiasi codice, qualsiasi throw, qualsiasi return anticipato ... */
    if (error) return;                     // il distruttore gira QUI. Widget cancellato. Automaticamente.
}                                          // e qui. Niente leak. Niente delete. Niente spazio tra le righe.
```

`std::unique_ptr<T>` è un wrapper di puntatore che possiede il suo oggetto esclusivamente e lo cancella nel distruttore — RAII, applicato ai puntatori, esattamente come promesso. Ed è a *costo zero*: `sizeof(std::unique_ptr<Widget>) == sizeof(Widget*)`, la stessa dimensione del puntatore raw, niente reference counting, niente control block — il wrapper è compilato via, e il codice macchina è identico alla versione con puntatore raw. La sicurezza è gratis. Questa è la riga più importante di questo manuale:

**`std::make_unique<Widget>()` sostituisce `new Widget()`, dappertutto, sempre, gratis.** `new` resta nel linguaggio per le implementazioni dei contenitori, e per te è in pensione. La morte di `delete` è reale: i codebase C++ moderni — Chromium, LLVM, i sistemi di trading del capitolo 13 — non contengono quasi nessun `new`/`delete` nudo, e il quasi-nessuno è il record di sicurezza: intere classi di vulnerabilità (i leak, i double-free, gli use-after-free) sono strutturalmente impossibili quando la proprietà è espressa nei tipi.

**Le move, precisamente.** `unique_ptr` è movable ma non copiabile — la proprietà *si trasferisce*, e il trasferimento è la migrazione del capitolo 8, applicata alla proprietà:

```cpp
auto a = std::make_unique<Widget>();
auto b = std::move(a);          // la proprietà passa da a a b. `a` ora è nullptr.
// auto c = b;                  // non compila: la proprietà esclusiva non si può copiare. Il "no" compila.
```

Il non compilare è il compilatore che impone il modello di proprietà: un oggetto, un proprietario, e il modello è la cosa che rende i leak impossibili. E il modello è la ragione per cui `unique_ptr` è il *default*: ogni puntatore possessore nel codice moderno è `unique_ptr` a meno che non ci sia una ragione misurata per il contrario.

**`std::shared_ptr`, precisamente, e l'avvertimento.** Proprietà condivisa — reference counted:

```cpp
#include <memory>

void sharedWay() {
    auto a = std::make_shared<Widget>();   // un oggetto, control block, contatore = 1
    auto b = a;                            // contatore = 2: entrambi lo possiedono
    a.reset();                             // contatore = 1
}                                          // b muore: contatore = 0: il Widget è cancellato. Automaticamente.
```

`shared_ptr` è RAII con un contatore: l'oggetto muore quando muore l'ultimo proprietario. E *non* è gratis: il control block (due contatori — strong e weak — più il deleter) è un'allocazione heap, e le copie sono incrementi atomici, e gli incrementi atomici sono contesi nel codice multithread. L'avvertimento, dai professionisti: **la proprietà condivisa è un design smell, la maggior parte delle volte.** Se sai chi possiede l'oggetto, usa `unique_ptr`. Se non sai, il non sapere è il problema di design, e `shared_ptr` è la medicazione — a volte la medicazione giusta (cache, grafi, pattern observer), di solito quella sbagliata. La regola: `unique_ptr` di default; `shared_ptr` quando la proprietà è genuinamente condivisa *per design*; puntatori raw (`Widget*` o `Widget&`) per i riferimenti non possessori — un puntatore che non possiede non cancella, e il non cancellare è corretto.

**`std::weak_ptr`, il rompicicli.** L'unico vero pericolo dello shared_ptr: il ciclo. Due oggetti che si condividono a vicenda si tengono vivi a vicenda, e i contatori non raggiungono mai lo zero, e il leak è tornato — attraverso la correzione. `weak_ptr` osserva senza possedere:

```cpp
struct Node {
    std::shared_ptr<Node> next;        // possessore: la lista è tenuta viva
    std::weak_ptr<Node> prev;          // osservatore: il ciclo è rotto
};

void check(std::weak_ptr<Node> w) {
    if (auto locked = w.lock()) {      // l'oggetto è sopravvissuto? lock() dà uno shared_ptr o null
        /* usa *locked */
    }                                  // altrimenti: l'oggetto è morto mentre non guardavamo
}
```

`weak_ptr` è la risposta a "è ancora vivo?", e la risposta è un `lock()` di distanza, e il lock è l'onestà che i manuali della collezione promettono: la macchina dice *ancora vivo* o *andato*, e il dire è la cosa che il puntatore raw non ti ha mai dato — il puntatore raw diceva *qui*, e il *qui* era l'uso dopo il free.

Questo è il capitolo, ed è la migliore notizia di questo manuale: l'errore è corretto, la correzione è gratis, e la morte di `delete` è reale. Il codice C++ moderno non ha `new`/`delete` nudi, e il no-nudi è il record di sicurezza, e il record è la cosa che ti fa dormire alle 3 di notte — che è dove è cominciato questo manuale, e dove va il capitolo 10: la concorrenza, il posto dove muoiono le certezze single-thread, e nascono gli atomic.
