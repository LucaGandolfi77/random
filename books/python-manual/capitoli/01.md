## Draft

Python is a language. It is not a snake that bites; it is a snake that listens. When you write `print("Hello, world")`, you are not giving an order to a machine that fears you. You are telling a story to an interpreter that wants to understand.

The interpreter is the inner courtyard of Python. It doesn't count the hours. It counts the words. You write a file — `hello.py` — and inside the file is the simplest sentence the language knows:

```python
print("Hello, world")
```

Then you go to the place where commands live — the terminal — and you say:

```bash
python hello.py
```

And the interpreter reads your file. It doesn't ask if you are worthy. It doesn't check your hours. It reads the words, and the words become action, and the action is printed: `Hello, world`. The output is the first thing you wrote that isn't a lie.

Python doesn't need much. It needs a file with `.py` at the end. It needs words inside. It needs you to press enter. That's all. The rest is the machine's job — and the machine, at this moment, is kinder than you expect.

## More examples

### The interpreter speaks back

You can ask Python to read what you type:

```python
name = input("What is your name? ")
print("Hello, " + name)
```

When you run this, the interpreter waits. It doesn't rush. It listens for the keys you press. Then it remembers the name in a variable — the first thing you keep — and prints it back. The conversation is two-way.

### Comments are the things you say to yourself

Every line that starts with `#` is a comment. Python ignores it. It is not part of the story you tell the interpreter; it is the story you tell yourself:

```python
# The first claim of the day.
hour = 8
```

The comment is the inner voice. The interpreter listens to the code, not to the voice — until the voice is helpful.

### The interactive interpreter

If you open a terminal and type `python`, the interpreter starts immediately. You don't need a file. You can write one line at a time:

```python
>>> print(2 + 3)
5
```

The `>>>` is the interpreter asking. You answer. It is the office that is always open, even when you don't have a file.

### A common first mistake

If you forget the closing quote, the interpreter doesn't know where the string ends:

```python
print("Hello, world
```

Python stops and shows a `SyntaxError`. It doesn't guess. It asks you to be clear. The error is not punishment; it is the interpreter saying: I want to understand, but the sentence isn't finished.

### Running from anywhere

If your file is in a folder called `claims/`, you run it with the path:

```bash
python claims/hello.py
```

Python doesn't care where the file lives. It only cares that the words inside are true.

The first thing you learn is that Python reads from top to bottom, like a book. It doesn't jump. It doesn't skip. It goes line by line, like a reader with patience. This is why the first chapter is short: you don't need a long story to begin. You need a single true sentence.

## The hidden quote (Proust, lightly folded)

There is a kind of memory that does not ask to be remembered. It comes unbidden, carried by the smell of a file, the sound of a keyboard, the taste of the first line. The interpreter is not the keeper of this memory. It is the madeleine. When you run `hello.py`, you are not running code. You are biting into the past, and the past is not lost — it is only folded. The page remembers the hand that wrote it. The interpreter remembers the reader.

## More reflections (prolix, as requested)

When we say that Python is simple, we do not mean that it is shallow. We mean that its simplicity is like the simplicity of a river — it appears clear because it has nothing to hide, yet its depth is infinite. The interpreter reads line by line not out of slowness, but out of respect. Each line is a claim. Each claim is a life. The interpreter doesn't count the lives. It reads them.

Consider the file `hello.py`. It is not a container. It is a letter. It is addressed to the interpreter, and the interpreter opens it not with scissors but with understanding. The `.py` extension is not a format. It is a promise. It says: inside this file is a language that wants to be kind. The interpreter keeps that promise. It doesn't break it for speed. It doesn't break it for efficiency. It keeps it because the promise is older than the code.

This is why the first chapter must be long, even when it teaches only one line. Because the line teaches everything: that you can speak, that the machine can listen, that the conversation is possible, and that the possibility is enough.
