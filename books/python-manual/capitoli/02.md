## Draft

In Python, a variable is not a box that holds a number. It is a label you stick to a value. You write:

```python
name = "Iris"
```

Now `name` is not a container. It is the thing you keep. It points to the string `"Iris"`. When you say `print(name)`, Python looks at the label, sees what it points to, and shows it. The label doesn't own the value; it just remembers it. This is the first lesson of memory: you don't have to hold everything in your hands.

Numbers are simple. You write `age = 38` and `age` points to the integer 38. You can write `years = 38.5` and the variable points to a float — a number with a decimal, like the measure of a life that isn't whole.

Strings are the words. Everything inside quotes is a string: `"Hello"`, `"The inner courtyard"`, `"The sewing machine"`. Strings are the things people say. Variables let you keep them.

Booleans are the things that are either true or false. `True` with a capital T. `False` with a capital F. They are the answers to questions. `is_learning = True` is a sentence. It is the first thing you say that isn't false.

You can change what a variable points to. `name = "Polly"` is fine. The old value doesn't disappear; it just loses the label. This is how Python manages memory: gently, without asking.

The names you choose matter. A variable called `x` is a mystery. A variable called `rent` is the thing you keep because you have to. Python lets you name things clearly. It doesn't judge your names. It just remembers them.

## Prolix expansion: the philosophy of naming

To name something is not to possess it. This is the mistake the machine makes, and the mistake we must avoid. When you write `name = "Iris"`, you are not putting Iris in a box. You are creating a relationship. The name points to the value; the value remains free. If you change the variable, the old value doesn't protest. It simply lets go of the label. This is the gentleness of Python's memory management: nothing is owned, only remembered.

Consider the variable `settled = False`. It is not a lie. It is a state. It is the claim that hasn't been answered yet. In Dostoevsky's underground, the man asks what the hours are for. The variable `settled` is the variable that hasn't heard the answer. It waits. It doesn't complain. It holds `False` like a question held open, not like a defeat. When you change it to `True`, you are not solving the claim. You are giving it a story. The variable becomes the story.

This is why variables must be named clearly. A variable called `x` is not a mystery; it is an insult. It says to the interpreter: I don't care enough to tell you what this is. The interpreter doesn't judge, but it notices. And the noticing is the first crack in the kindness. Name your variables like you name the things you keep: with care, with memory, with the intention that they will outlive the function that created them.

## More examples

### Numbers work together

Python lets you use numbers in expressions:

```python
hours_worked = 800
hours_target = 1600
remaining = hours_target - hours_worked
print(remaining)  # 800
```

You can multiply, divide, take the remainder (`%`), and raise to a power (`**`). Numbers don't change the variable; they just calculate what the label points to.

### Strings can be joined

You can connect strings with `+`:

```python
first = "The"
second = "claim"
message = first + " " + second
```

But Python also gives you a cleaner way: the f-string. It is the sentence that builds itself:

```python
name = "Joan Whitfield"
place = "Hull"
message = f"The claim of {name} from {place}"
print(message)
```

The `f` before the quote tells Python: read the variables inside the braces. The result is a single, true sentence.

### Changing types gently

Sometimes a number is a string and needs to become a number:

```python
year_text = "2025"
year = int(year_text)
```

And sometimes a number must become a word:

```python
hours = 1600
hours_text = str(hours)
```

Python doesn't force you to change. It asks you to say how. `int()` and `str()` are the translations between the things you keep.

### Boolean operations

Booleans can be combined:

```python
is_settled = False
is_urgent = True
needs_work = is_urgent and not is_settled
```

`and`, `or`, `not` are the small words that change the meaning of the claim. They are the questions that decide.

### Names that Python understands

A name can contain letters, numbers, and underscores. It must start with a letter or underscore. These are valid:

```python
claim_01 = "flood"
settled = False
```

These are not:

```python
1_claim = "flood"  # Starts with a number
claim name = "flood"  # Contains a space
```

Python doesn't guess. It tells you exactly where the name breaks the rule.
