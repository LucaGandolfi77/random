## Chapter notes

Functions in Python are simple. They start with `def`. They take inputs (arguments). They return outputs (values). They are the things you keep doing, and naming them is how you don't forget.

---

## Draft

Every time you do the same thing twice, you should name it. In Python, you name it with `def`:

```python
def greet(name):
    return "Hello, " + name
```

Now `greet` is not a word; it is a process. It takes a name, and it gives back a greeting. You call it with `greet("Iris")`. Python remembers the function because you named it. This is the first small thing you plant: it grows every time you call it.

Functions take arguments. You can pass one, many, or none:

```python
def add_hours(a, b):
    return a + b

total = add_hours(800, 800)
```

The arguments are the things the function needs. They are not the things you keep forever; they are the things you pass for a moment, like the sewing machine in the claim: used, then returned.

Functions can return nothing. In Python, if you don't say `return`, the function returns `None`. `None` is the empty label. It is the thing that isn't false, but isn't anything either. It is useful: sometimes the answer is that there is no answer.

You can give arguments default values:

```python
def greet(name, greeting="Hello"):
    return greeting + ", " + name
```

The default is the thing you keep when nothing else is given. It is the habit. It is the small repeated thing.

Functions can call other functions. A function is not isolated. It is part of the inner courtyard: it connects to everything else. You can build a function that calls `add_hours`, then `greet`, then `print`. The order is the story.

## More examples

### Arguments with names

You can pass arguments by name. This makes the call clear, even when you forget the order:

```python
def settle_claim(name, amount, settled=False):
    return f"{name} settled for {amount} (settled: {settled})"

print(settle_claim(name="Joan Whitfield", amount=4200, settled=True))
```

This is the claim that knows exactly what it is. The names don't just point; they describe.

### Returning more than one thing

A function can return a tuple — the things you hold together:

```python
def split_hours(hours):
    worked = hours // 2
    remaining = hours - worked
    return worked, remaining

w, r = split_hours(1600)
print(w, r)  # 800 800
```

This is the claim that gives back two answers at once. It is the small repeated thing that doesn't hide anything.

### The docstring: the story inside the function

Every function can carry its own explanation:

```python
def count_claims(claims):
    """Returns the number of unsettled claims."""
    return len([c for c in claims if not c.get("settled", False)])
```

The triple quotes are the inner voice of the function. Python doesn't read them as code. It keeps them for anyone who asks `help(count_claims)`.

### Lambda: the small unnamed thing

Sometimes you need a function that is too small to name:

```python
square = lambda x: x ** 2
print(square(10))
```

`lambda` is the claim without a file. It lives in the line where it is born. It is the small repeated thing that doesn't need a house.

### Scope: the things that belong to the room

A variable created inside a function stays inside. It doesn't leak into the office:

```python
def calculate():
    temp = 1600  # This variable lives only in this room.
    return temp // 2

# print(temp)  # This would break. The variable is gone.
```

This is the inner courtyard with doors. The function has its own things. It returns what it wants to share.

### A simple recursion

A function can call itself, as long as it knows when to stop:

```python
def count_down(n):
    if n <= 0:
        return "Done."
    return count_down(n - 1) + " " + str(n)
```

This is the loop that has given its name to itself. It is the small repeated thing that remembers its own story.
