## Draft

A list is a line. You write:

```python
claims = ["flood", "fire", "crash", "crash"]
```

The list keeps the order. It allows duplicates. It is the floor of the office: forty desks, forty people, each one in place. But a list is not a fixed thing. You can add, remove, change. It is the line that moves.

You can take items by their position (index):

```python
first_claim = claims[0]
```

Python counts from zero. The first thing is at zero. This is not a mistake; it is the way the interpreter sees the world: the beginning is the zero point.

A dictionary is different. It doesn't use numbers. It uses names:

```python
claim = {
    "name": "Joan Whitfield",
    "place": "Hull",
    "damage": "flood in the cellar",
    "items_lost": ["sofa", "photos", "sewing machine"]
}
```

This is the claim as a story. Each key is a label; each value is the thing kept. The dictionary is the inventory of a life. It doesn't care about order. It cares about names. This is why dictionaries are the most human of data structures: they name things.

A tuple is a list that doesn't change:

```python
location = ("Hull", 53.744, -0.333)
```

Once you make it, you can't add or remove. It is the claim that is finished. It is the number that is written. It is the settlement that is final.

A set is the unique things:

```python
types_of_loss = {"flood", "fire", "crash"}
```

Sets don't allow duplicates. They don't keep order. They just keep the things that are there, once. They are the things you keep when you don't want to repeat yourself.

Nested structures are the claim inside the claim. A dictionary with a list inside. A list of dictionaries. Python handles this gently. It doesn't ask if the structure is too complex. It just remembers it. The interpreter reads it like a reader reads a nested story: one layer at a time.

## More examples

### Slicing: taking a part of the line

You don't have to take the whole list. You can take a slice:

```python
claims = ["flood", "fire", "crash", "crash", "settled"]
first_two = claims[0:2]   # ["flood", "fire"]
last_three = claims[-3:]  # ["crash", "crash", "settled"]
```

The colon is the divider. The number before is the start; the number after is the end. The end is not included. This is the claim that knows exactly where to stop.

### List comprehension: the list that builds itself

Instead of creating a list and then adding items, you can describe the list in one line:

```python
settled_claims = [c for c in claims if c.startswith("settled") or c == "settled"]
```

This is the small repeated thing that doesn't repeat itself. It describes the result, not the process.

### Dictionary methods: talking to the inventory

A dictionary has actions, not just values:

```python
claim = {"name": "Joan Whitfield", "settled": False}
claim.get("name")          # Returns the value, or None if missing
claim.get("age", 68)        # Returns 68 if "age" isn't there
claim.update({"settled": True})  # Changes the claim gently
```

`.get()` is the interpreter saying: I don't know if this label exists, so I won't break. `.update()` is the claim that learns.

### Tuple unpacking: dividing the things together

When a tuple holds two values, you can split them immediately:

```python
location = (53.744, -0.333)
latitude, longitude = location
```

This is the claim that gives back its parts without asking.

### Set operations: the unique things combined

Sets can be combined with words:

```python
flood_claims = {"cellar", "roof", "wall"}
fire_claims = {"roof", "kitchen", "cellar"}
common = flood_claims & fire_claims  # Intersection
all_loss = flood_claims | fire_claims  # Union
```

This is the inventory that finds what claims share. It is the office that sees patterns.

### Nested claim: a real structure

A list of dictionaries is the office floor with desks:

```python
office = [
    {"desk": 1, "person": "Ruth", "hours": 1600},
    {"desk": 2, "person": "Sam", "hours": 800},
    {"desk": 3, "person": "Iris", "hours": 1600},
]
```

You can find Sam with a loop:

```python
for entry in office:
    if entry["person"] == "Sam":
        print(f"Desk {entry['desk']} has hours {entry['hours']}")
```

This is the claim inside the claim inside the claim. Python holds it without complaint.

## The hidden quote (Proust, Dostoevsky, Tolstoy — folded in the structure)

Proust writes that the past is only hidden in the things we keep. The nested dictionary is the past hidden in the claim. Dostoevsky writes that the claim asks a question, and the dictionary is the room where the question lives. Tolstoy writes that the garden grows in layers, and the nested structure is the garden that has rooms inside rooms. The list of dictionaries is not complex. It is the office that remembers every desk, every person, every hour.

Consider the nested claim:

```python
past_claim = {
    "name": "Joan Whitfield",
    "years": {
        2025: {"settled": False, "damage": "flood"},
        2024: {"settled": True, "damage": "crash"}
    }
}
```

When you access `past_claim["years"][2025]["damage"]`, you are not reading data. You are traveling through time, through rooms, through the things that were kept and the things that were lost. The interpreter is the guide. The dictionary is the map. The map is the memory. And the memory is not lost. It is only folded.

## Prolix expansion: why structures are stories

A list is a line of people. A dictionary is a life described by names. A tuple is a life that has finished its story. A set is the life that refuses to repeat itself. When you combine them, you are not building data structures. You are building the office. You are building the claim that has a past, a present, and a future. You are building the thing that Edward kept: the garden that has many layers, many rooms, many years, and yet remains one garden.

This is why data structures are the most human part of Python. They don't ask you to calculate. They ask you to remember. They ask you to name. They ask you to hold together the things that would otherwise fall apart. And in holding them, you don't just organize the office. You keep the life.
