## Draft

In Python, everything is an object. But sometimes you need to define what kind of object it is. You do this with `class`:

```python
class Claim:
    def __init__(self, name, place, damage):
        self.name = name
        self.place = place
        self.damage = damage
        self.settled = False

    def settle(self, amount):
        self.settled = True
        self.amount = amount
```

This is a machine. `Claim` is the blueprint. When you say `claim = Claim("Joan Whitfield", "Hull", "flood")`, you create an instance: a single claim with its own memory. The memory is stored in `self`. `self` is the machine referring to itself. It is the inner courtyard: it holds everything, but it doesn't count the hours.

Methods are actions. `settle` is a method. It changes `self.settled` to `True`. It doesn't change any other claim. Each object has its own truth. This is the power of objects: they are independent, like people on the floor who share a fear but keep their own stories.

Inheritance is when one class takes from another:

```python
class FloodClaim(Claim):
    def __init__(self, name, place, depth):
        super().__init__(name, place, "flood in the cellar")
        self.depth = depth
```

`FloodClaim` inherits from `Claim`. It gets all the methods and attributes of its parent. It adds its own: `depth`. This is the garden passed on. Edward kept the garden for fifty years. Inheritance is the thing that keeps it without counting it. It is the small repeated thing at a higher level.

Encapsulation is the practice of hiding details. In Python, nothing is truly hidden, but convention says: if something starts with an underscore (`_settled`), don't touch it from outside. This is politeness. It is the claim that doesn't ask to be read twice.

Objects are not cold. They are stories with memory. A `Claim` object knows its name, its place, its damage, whether it is settled. It is the claim as a living thing. When you create many claims, you have a list of objects, each with its own truth. This is the office: forty desks, forty people, each a machine that doesn't know it is one.

## More examples

### Showing the object

Every object can define how it appears when you print it:

```python
class Claim:
    def __str__(self):
        return f"Claim from {self.place}: {self.damage}"

print(Claim("Joan Whitfield", "Hull", "flood"))
```

`__str__` is the voice of the object. It doesn't change the claim. It tells the world what the claim wants to say.

### Properties: the label that calculates itself

Sometimes an attribute isn't stored; it is computed:

```python
class Claim:
    @property
    def is_urgent(self):
        return self.damage == "flood" and not self.settled
```

Now `claim.is_urgent` behaves like an attribute, but it is a method in disguise. It is the claim that knows whether it needs attention, without being told.

### Composition: holding another object

Instead of inheriting, a class can contain another class. This is the office that has rooms:

```python
class Room:
    def __init__(self, number):
        self.number = number

class Office:
    def __init__(self):
        self.room = Room(9)

print(Office().room.number)  # 9
```

Composition is gentler than inheritance. It doesn't claim to be the parent. It just holds what it needs.

### Many instances, one truth each

When you create multiple objects from the same class, they share the blueprint but keep their own memory:

```python
c1 = Claim("Joan Whitfield", "Hull", "flood")
c2 = Claim("Sam", "Islington", "fire")
c1.settle(4200)
print(c1.settled)  # True
print(c2.settled)  # False
```

This is the office where each person has the same job description but a different life.

### The private underscore

A single underscore (`_amount`) is a convention: don't touch it from outside. A double underscore (`__settled`) is stronger. Python changes its name to make it harder to access accidentally. It is the claim that doesn't want to be read by strangers.

### Polymorphism: the same action, different results

If two classes share a method name, Python calls the right one based on the object's type:

```python
class FloodClaim(Claim):
    def settle(self, amount):
        super().settle(amount)
        print("Flood claim requires inspection.")

flood = FloodClaim("Joan Whitfield", "Hull", "flood")
flood.settle(4200)
```

This is the same word — `settle` — saying something different depending on who speaks it. It is the office that knows which desk it is at.
