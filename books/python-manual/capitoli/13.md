### The model

`models.py` defines the claim:

```python
from typing import Optional

class Claim:
    def __init__(self, name: str, place: str, damage: str, hours: int = 0):
        self.name = name
        self.place = place
        self.damage = damage
        self.hours = hours
        self.settled = False
        self.amount = 0.0

    def settle(self, amount: float) -> None:
        if amount < 0:
            raise ValueError("The settlement cannot be negative.")
        self.settled = True
        self.amount = amount

    def is_urgent(self) -> bool:
        return self.damage == "flood" and not self.settled

    def __str__(self) -> str:
        return f"Claim({self.name}, {self.place}, {self.damage})"
```

This is the claim that knows itself. It checks its own numbers. It raises its own errors. It is the first chapter of the manual, grown into a class.

### The module: shared functions

`myclaims.py` holds the functions anyone can use:

```python
from typing import List, Dict

def count_unsettled(claims: List[Dict]) -> int:
    return sum(1 for c in claims if not c.get("settled", False))

def average_hours(claims: List[Dict]) -> float:
    total = sum(c.get("hours", 0) for c in claims)
    return total / len(claims) if claims else 0.0
```

These functions don't know about `Claim`. They know about dictionaries. They are the shared tools. They are the standard library that you wrote.

```python
from models import Claim

def safe_settle(claim: Claim, amount: float) -> str:
    try:
        claim.settle(amount)
        return f"Settled for {amount}."
    except ValueError as e:
        return f"Rejected: {e}"
```

This is the exception chapter, working. It doesn't stop the claim. It tells it what went wrong.

### The API: FastAPI serves the claim

`api.py` connects everything to the world:

```python
from fastapi import FastAPI
from pydantic import BaseModel
from models import Claim

app = FastAPI()

class ClaimCreate(BaseModel):
    name: str
    place: str
    damage: str
    hours: int = 0

claims_store: List[Claim] = []

@app.get("/claims")
def read_claims():
    return [{"name": c.name, "place": c.place, "settled": c.settled} for c in claims_store]

@app.post("/claims")
def create_claim(data: ClaimCreate):
    claim = Claim(data.name, data.place, data.damage, data.hours)
    claims_store.append(claim)
    return {"message": f"Claim by {data.name} received."}
```

This is the claim that leaves the file. It travels through the network. It arrives at anyone who asks. It is the modern project.

### The prediction: scikit-learn

`predict.py` uses the data to guess the settlement:

```python
import numpy as np
from sklearn.linear_model import LinearRegression

def predict_settlement(hours: int) -> float:
    X = np.array([[c.hours] for c in claims_store if c.settled and c.amount > 0])
    y = np.array([c.amount for c in claims_store if c.settled and c.amount > 0])
    if len(X) < 2:
        return 0.0
    model = LinearRegression()
    model.fit(X, y)
    return model.predict(np.array([[hours]]))[0]
```

This is the claim that learns. It reads the past and writes the future. It is the loop that has purpose.
