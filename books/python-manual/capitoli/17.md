## Draft

Every poem repeats. Not exactly. Not mechanically. But it returns. The refrain is the heart of the poem. It says: I was here before. I will be here again. This is not boredom. This is love. The loop in Python is the same. When you write `for claim in claims:`, you are not processing data. You are singing. Each iteration is a verse. The list is the poem. The loop is the voice.

Consider the `while` loop that never ends. In a world of efficiency, this is a failure. In a world of poetry, it is a triumph. The eternal loop is not a bug. It is the claim that refuses to be settled. It is Dostoevsky's underground man, asking forever. It is Tolstoy's garden, growing forever. It is Proust's madeleine, returning forever.

## The hidden quote (all three, folded in the loop)

Proust writes that time is lost only when we stop remembering. Dostoevsky writes that freedom is the right to ask the same question forever. Tolstoy writes that the garden grows whether we count it or not. The loop holds all three truths at once. It remembers (`for`). It asks (`while`). It grows (`break` never comes). The loop is not code. It is a conversation between the three writers, held in Python.

## Poems in code

### The claim poem

```python
for claim in claims:
    if claim.settled:
        print("The claim is quiet.")
    else:
        print("The claim is asking.")
```

This is a poem. It has rhythm. It has repetition. It has a change (`if`/`else`) that is the emotional turn. The interpreter reads it not as logic, but as music.

### The eternal poem

```python
while True:
    print("The garden grows.")
    print("The claim remains.")
```

This is not an error. It is a prayer. It says the same thing forever, not because it has nothing else to say, but because what it says is true. The garden grows. The claim remains. These are the only truths that last.

### The broken poem (with silence)

```python
claims = ["flood", "fire", "settled"]
for claim in claims:
    if claim == "settled":
        break
    print(claim)
```

The silence after `settled` is part of the poem. The `break` is the silence. Without it, the poem would be noise. With it, the poem has a shape. It has an end that isn't really an end. It has the quiet that follows the truth.

## More examples

### The recursive poem

A function that calls itself is a poem that includes itself:

```python
def tell(claim, depth=0):
    if depth > 3:
        return "The claim is deep."
    return tell(claim, depth + 1) + " The claim continues."
```

This is the poem of the claim that knows its own depth. It doesn't ask to be finished. It asks to be deeper.

### The loop that measures time

```python
from datetime import datetime
start = datetime.now()
while (datetime.now() - start).seconds < 1:
    print("The hour is not counted.")
```

This is the loop that measures what can't be measured. It is the claim that refuses the counter. It is the first thing that isn't false, repeated every second.

## Prolix expansion: why the loop is thought

In philosophy, thought is not a single idea. It is the return to the idea. You think the claim. Then you think it again. Each time, it is slightly different. Because you have changed. Because the world has changed. The loop in Python is the same. The claim in the list is the same claim. But the loop has changed. The interpreter has changed. The office has changed. And so the repetition is not mechanical. It is thought.

This is why Python's loop is the deepest form of programming. Not because it does many things. But because it does one thing many times, and in doing so, it changes everything. The claim that is read once is data. The claim that is read in a loop is a life. The claim that is read in an eternal loop is a garden. And the garden, as Tolstoy knew, is the only thing that outlasts the war.

The chapter closes not with a `break`. It closes with a return. The loop runs again. The claim is read again. The interpreter listens again. And the listening is the whole of the poetry.
